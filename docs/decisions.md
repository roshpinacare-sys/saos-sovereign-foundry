# החלטות הנדסיות — SAOS Sovereign Foundry v2

עודכן: 2026-09-07 · פורמט: מה הוחלט / למה / חלופות / סיכון / תועלת / מאישור

## D1 — פורט הקרנל מ-CJS ל-TypeScript במקום להריץ את הקוד ההיסטורי כמו שהוא

- **מה**: `sovereign/core/kernel.cjs` מארכיון steem-main נכתב מחדש כ-`src/lib/saos/kernel.ts` (ועמו canonical-json, merkle, evidence).
- **למה**: סטאק אחיד (Next 16 + TS), טיפוסים קפדניים, אין גשר node-child בזמן-ריצה; הדיסציפלינה (GAS, dedupe, fail-closed) נשמרה 1:1 ומתועדת בכותרות הקבצים.
- **חלופות שנבחנו**: (א) להריץ את ה-node ההיסטורי כשירות צד — נדחה: תלות כפולה וסטייה סביבתית; (ב) להשאיר את הקוד המקורי כ-src-of-truth ולקרוא אליו — נדחה מאותן סיבות.
- **סיכון**: סטייה בין הפורט למקור. הפחתה: selftest תכונה (7 בדיקות) + תיעוד מקור בכל קובץ.
- **תועלת**: בדיקות-זמן-ריצה, שילוב UI/API מיידי, אין גבול בין שכבות.
- **מאישור**: המשתמש (הנחיה "להקים מחדש ברמה גבוהה הרבה יותר") — worklog Task 2.

## D2 — API לעולם לא מחזיר 500 (שגיאה היא נתון)

- **מה**: כל route עוטף הכול ב-try/catch ומחזיר `{ok:false, error}` עם HTTP 200.
- **למה**: כלל ברזל של המשתמש; גייטוויי/צרכנים לא נשברים על 500; שגיאה הופכת ניתנת-להצגה ב-UI.
- **חלופות**: קודי HTTP תקניים (4xx/5xx) — נדחה מול הכלל.
- **סיכון**: מערכות ניטור שמסתמכות על קודי-סטטוס לא יראו כשל; תשובות שגיאה יכולות להישמר ב-cache אם יתווסף CDN.
- **תועלת**: עמידות, חוויה עקבית, שקיפות הודעות.
- **מאישור**: המשתמש (כלל קבוע).

## D3 — מצב advisory לעגינה (אין מפתחות בסנדבוקס) במקום ביום txid

- **מה**: seal מחשב/שומר שורשים ומסמן STEEM/BLURT=pending, HIVE=gated, TRON=transit עם סיבה; `txid:null`.
- **למה**: כנות מעל תיאטרון — העיקרון המרכזי שהוכיח את עצמו במחקר (qodo: "האב-הקדום היה תיאטרון"); txid מבוים יהרוס את ערך הראיות.
- **חלופות**: לייצר txid מדומה לתצוגה — נדחה באופן קטגורי.
- **סיכון**: ממשק פחות "מרשים" — מקובל.
- **תועלת**: אמון מוכח-שחזור; מעבר ל-live הוא החלפת סטטוסים בלבד, לא שכתוב.
- **מאישור**: המשתמש ("כנות, לא תיאטרון") — ניכר בקוד ההיסטורי ובדרישות.

## D4 — SQLite דרך Prisma

- **מה**: provider sqlite, קובץ `db/custom.db`, `db push` ללא migrations.
- **למה**: מוגבל סביבת סנדבוקז; אפס תשתית; הסכימה ניידת ל-Postgres בשינוי provider.
- **חלופות**: Postgres/MySQL — אינן זמינות בסביבה; Redis — לא רלוונטי.
- **סיכון**: ריבוי-מופעים, מירוצים (F1), תורפות W1–W5 ב-database.md.
- **תועלת**: שחזור מלא מהריפו בשלוש פקודות.
- **מאישור**: מובנה בסטאק הפרויקט.

## D5 — canonical JSON בלי float (שלמים בלבד)

- **מה**: `canonicalize` דוחה כל מספר לא-שלם; payloads של rc/economy מקודדים per-mille (×10) ו-micro-units (×100).
- **למה**: digests יציבים בין פלטפורמות ושפות; עיגול-נקודה-צפה הוא מקור באגים של שלמות.
- **חלופות**: קנוניזציה של float (שברים קבועים) — נדחה: מורכבות נגד תועלת בשלב זה.
- **סיכון**: קלט חוץ עם float נדחה — מכוון (fail-closed).
- **תועלת**: שחזור ביטקייט; באג 1 מסבב הבנייה נלכד ע"י המנגנון הזה.
- **מאישור**: מורשת הקרנל ההיסטורי (worklog Task 1).

## D6 — שרשרת קבלות בתוך ה-DB עם prevDigest=האחרונה

- **מה**: כל פעולה ראויה-ראיה מחוללת EvidenceReceipt; prevDigest מצביע על הקבלה האחרונה לפי createdAt.
- **למה**: טמפר-אבידנס זול; מציג גבול-אמת מפורש.
- **חלופות**: מרקל-צבירה תקופתית; עוגן חוץ מיידי — עתידי (שלב 2+).
- **סיכון**: פיצול-שרשרת בכתיבה כמעט-מקבילה (F2); unique(digest) בריצה זהה (F3 — מטופל).
- **תועלת**: רצף-הוכחה נצפה ב-UI וב-API.
- **מאישור**: פורט דיסציפלינת qodo/V33.30.

## D7 — שערי Hive כנים עם מתמטיקת התאוששות

- **מה**: ספי RC 8%/12% + רגן 20%/יום (ליניארי) → מחשבון שעות-עד-יעד + מסלול power-up.
- **למה**: הסיבה המדודה האמיתית להמתנה (rc 0.6%<12% בריצה החיה) — להפוך חסם מתועד לכלי.
- **חלופות**: לעגן HIVE בכוח מעל הסף — נדחה: נכשל ברשת, מביך.
- **סיכון**: מודל ליניארי הוא קירוב של רגן-קוביות אמיתי — מסומן.
- **תועלת**: תכנון פעימות מדויק.
- **מאישור**: מורשת steem-main hive_rc.cjs.

## D8 — tron-energize כמודול מתמטי במקום רכיב חתימה מיידי

- **מה**: `planEnergize` מחשב freezeBalanceV2/delegateResource/יישובים/break-even; אין שידור.
- **למה**: זה החוסר המזוהה #1 בכל 10 הארכיונים; המתמטיקה קודמת לחתימה (שדורשת TRX ממומן + כספת).
- **חלופות**: לשלב tronweb מיידית — נדחה: תלות כבדה ללא כספת בצד.
- **סיכון**: פרמטרי רשת (420 sun/energy, 10 energy/TRX/day) נעים — קונפיגורביליים ומסומנים.
- **תועלת**: כשיהיה TRX — התוכנית מוכנה בביטים.
- **מאישור**: המשתמש בירך שימוש ב-TRX באופן אקטיבי.

## D9 — מבנה שלושה-ריפואים (foundry + platform + baseline)

- **מה**: `saos-sovereign-foundry` (הפרויקט החי), `saos-sovereign-platform` (עותק בלתי-תלוי מדורג), `anchor-baseline` (שחזור מדויק של 5356dab).
- **למה**: הנחיית המשתמש — תיקיית-קומיט שלי + תיקיית-עבודה משותפת; הפרדת שימור מהתפתחות.
- **חלופות**: ריפו יחיד עם תיקיות — נדחה: לא עמדה בהנחיה.
- **סיכון**: דריפת סנכרון בין הריפואים; ה-foundry הוא המקור.
- **תועלת**: שרידות; נקודת-השוואה היסטורית.
- **מאישור**: המשתמש — worklog Task 2-push.
