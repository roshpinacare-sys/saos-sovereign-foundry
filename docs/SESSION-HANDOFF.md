# SESSION-HANDOFF — תבנית מסירת-מושב קנונית של הרשת

> **מקור-השראה**: תבנית `NEXT_SESSION_PROMPT` מ-ecos (ZIP `ecos_v568_canonical.zip` →
> `NEXT_SESSION_PROMPT_V526.md` / `_V568.md` — נקרא סטטית בלבד, מעולם לא הורץ),
> נכתבה מחדש למחסנית שלנו: foundry + AGENTS.md + chief-of-staff + vault-guardian.
>
> **מי משתמש**: כל סוכן תורן שמסיים סשן ממלא את התבנית הזו ומדביק אותה
> (בסוף הרשומה ב-worklog או בפתיחת המשימה הבאה ב-next-steps). מי שנכנס — קורא קודם כל.
> **עיקרון מהמקור שחובה לשמר**: exit-code truth — כל קביעה עם פקודה+פלט צפוי,
> וחובה סעיף "מה לא אומת". סטטוס בלי ראיה = לא נכתב.

## תבנית (מלא והדבק — אל תשמור על המצב הזה בראש, שמור אותו בריפו)

```markdown

יורש/ת את המושב של <סוכן/משימה>. מטרת המושב הבא: <מטרה אחת בשורה>.

## Pre-flight (הרץ קודם כל — ודא שהפלטים תואמים, אחרת עצור וחקור)
```bash
git -C /home/z/my-project rev-parse --short HEAD   # צפוי: <HEAD-40חומרה> (Task <N> נדחף)
curl -s localhost:3031/status | head -c 200        # צפוי: guardian, devMode, token.present
curl -s localhost:3032/status | head -c 200        # צפוי: chief-of-staff, tick alive
ls docs/briefings/latest.md && date -r docs/briefings/latest.md  # צפוי: בריף <24 שעות
tail -n 40 worklog.md                              # צפוי: הרשומה האחרונה = Task <N>
bun run release-truth-audit                        # צפוי: <X>/6 PASS (ראה פירוט למטה)
```

## מצב רגע-המסירה (state snapshot)
- **HEAD**: <short-sha> — "<נושא-ה-commit האחרון>" (דחיפה אומתה: <כן/לא + ראיה>)
- **שירותים**: guardian :3031 <חי/מת + ראיה> · chief-of-staff :3032 <חי/מת + ראיה> ·
  פיתוח next :3100 (Task 10) <רץ/כבוי>
- **בריף אחרון**: docs/briefings/BRIEF-<ts>.md — שורת-המצב המרכזית ממנו: <ציטוט קצר>
- **release-truth-audit**: <X>/6 — מה נכשל ולמה: <שורה לכל נכשל, או "הכל ירוק">

## מה בטוח (מאומת, אמת-קוד-יציאה)
- <קביעה> — ראיה: <פקודה/קובץ:שורה/פלט>. 
- <קביעה> — ראיה: <...>
(רק מה שהרצת בעצמך במושב הזה. מה שלא הרצת — למטה.)

## מה שברירי / לא מאומת (חובה — היושר הוא המוצר)
- <מה שכתבת אבל לא הרצת / לא בדקת עצמאית / תלוי בשירות חיצוני / עבודה של סוכן אחר>
- <טכני-חוב: מה נשאר גס בכוונה ולמה>
- "מה לא אומת" חובה לפי כללי ecos — סוכן שלא משאיר סעיף כזה = הרשומה פגומה.

## הצעד הבא המומלץ (בחר אחד — הזול שסוגר את הממצא הכי כנה)
- **A — <שם>**: <משפט>. שימושי ל-<מי>. מוגבל ל-<תחום>.
- **B — <שם>**: <משפט>. ⚠️ <מכשול/תיאום-נדרש>.
- **המלצה: A** — <למה>.

## כללי never-clobber (חוקיים — לא המלצות)
- **worklog.md**: append בלבד (>>). אסור overwrite/ריוורייט — גם לתיקון-עצמי.
  תיקון-עצמי = רשומה חדשה גלויה (AGENTS.md משמעת-תיעוד).
- **git**: לפני push — `git fetch`; אם ה-remote זז: אל תדרוס, דווח והמתן החלטה. 
  force-push אסור (החרגה יחידה: guardian בפרודקשן GUARDIAN_DEV_MODE=0).
- **קבצים של סוכנים אחרים**: אל תשנה טסט/דוק/מודול שסוכן אחר בבעלותו בלי תיאום
  (מקבילת הכלל מ-ecos: "זה טסט של שותף אחר — אל תשנה ללא תיאום").
- **docs/briefings/**: ראש-המטה הכותב היחיד; סוכן תורן לא מכתיב לו.
- **מפתחות/סודות**: לא להדפיס ערכים; נתיב+מחלקה בלבד; טוקן רק דרך GIT_ASKPASS.

## שלוש-הפעולות-הראשונות ליורש
1. <פעולה קונקרטית + הפקודה, למשל: קרא 2 רשומות worklog אחרונות + זנב next-steps>
2. <פעולה, למשל: הרץ bun run release-truth-audit והשווה ל-X/6 שלמעלה>
3. <פעולה, למשל: אמת שהשירותים חיים, ואם לא — הסתמך על supervisor/instrumentation להחיות>

## כללי-ברזל (רפרנס מהיר — המקור המחייב הוא AGENTS.md)
- תחום מוגבל בלבד; עבודה שהתגלתה בדרך → משימה חדשה ב-next-steps, לא הרחבה שקטה.
- הוכחה או שקט: כל קביעה עם file:line או פלט-פקודה.
- builder/verifier מופרדים: מימשת = implemented; רק אימות עצמאי = verified.
- קוד זר: אסור להריץ — סריקה סטטית בלבד (כלל-החבלן; כולל ZIPs ב-Project-files).
- אפס סודות בפלט/לוג/דוקומנטציה.
- סיום מושב: worklog (append, template רשמי) + next-steps + SESSION-HANDOFF מעודכן.

## מדוע התבנית הזו (שיקולי-ההתאמה)

1. **מה-ecos שאבנו**: החלוקה SAFE-מאומת / FRAGILE-לא-מאומת, ה-Pre-flight עם פלטים
   צפויים, כלל "חובה: מה לא אומת", והעיקרון שהמסירה היא מסמך בריפו ולא זיכרון-שיחה.
2. **מה שינינו למחסנית שלנו**: מקורות-אמת לפי AGENTS.md (worklog/next-steps/briefings),
   שירותי הרשת (guardian/chief-of-staff) במקום md5-של-libs, כללי never-clobber
   מפורשים, והפניה ל-acceptance-gates (docs/acceptance-gates.md) במקום כללי-גרסה של ecos.
3. **היכן לשמור גרסאות**: מסירה חדשה = רשומה חדשה (append), כמו worklog. התבנית הזו
   עצמה עוברת שינוי רק בהחלטה מתועדת (owner-decisions / decisions).
